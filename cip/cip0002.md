## Summary

Add structured, allowlisted bridle MCP tools for GitHub **Issues** and
**Discussions** so sandboxed agents can triage and answer maintainer workflows
(list/view/comment/close; Discussions answer-marking) without shell escape or
ad-hoc `gh api graphql` from the agent seatbelt.

**Trigger:** GPy Discussion hygiene (answer three / close three) could not be
done through bridle — only `gh_pr_*` is allowlisted; Discussions need GraphQL.

## Motivation

CIP-0001 shipped `ping` + `gh_pr_view` / `gh_pr_list` / `gh_pr_create`. Real
project maintenance (SheffieldML/GPy CIP-0007 trackers, usage Discussions,
Python-floor Ideas threads) needs **issues** and **discussions** next.

Constraints that remain:

- No free-form shell or arbitrary GraphQL from the agent  
- Prefer `gh` CLI where stable; use `gh api graphql` **inside** bridle with
  fixed query documents (not agent-supplied query strings)  
- Mutating ops stay audited via the action log  

## Detailed Description

### Tool surface (proposed)

| Tool | Mutating | Backend sketch |
|------|----------|----------------|
| `gh_issue_list` | no | `gh issue list --repo … --json …` |
| `gh_issue_view` | no | `gh issue view … --json …` |
| `gh_issue_comment` | yes | `gh issue comment … --body-file …` |
| `gh_issue_close` | yes | `gh issue close … [--reason …]` |
| `gh_issue_reopen` | yes | `gh issue reopen …` |
| `gh_discussion_list` | no | fixed GraphQL `discussions(first:)` |
| `gh_discussion_view` | no | fixed GraphQL `discussion(number:)` + comments |
| `gh_discussion_comment` | yes | `addDiscussionComment` mutation |
| `gh_discussion_close` | yes | `closeDiscussion` mutation |
| `gh_discussion_mark_answer` | yes | `markDiscussionCommentAsAnswer` (Q&A only) |

Optional later (not required for REQ-0002 acceptance): `gh_issue_create`,
`gh_discussion_create`.

### Design decisions

1. **Structured args only** — `repo`, `number`, `body`, `state`, `limit`,
   `category` (slug or id where needed). Never `query: str` from the agent.
2. **Fixed GraphQL documents** in `bridle/gh_graphql.py` (or similar) with
   variables only; versioned with the adapter.
3. **Policy** — extend `ALLOWED_TOOLS` in `policy.py`; mutating tools may later
   share CIP-0001 hardening “confirm” flag.
4. **Body size** — cap comment body length in the adapter (e.g. 64 KiB) to
   avoid accidental huge writes.
5. **Errors** — map `gh` / GraphQL failures to structured `{ok, error}` like
   existing PR tools; never leak tokens.

### Explicit non-goals

- Agent-authored GraphQL  
- Org-wide Discussion moderation  
- Replacing the GitHub web UI for complex edits  

## Implementation Plan

1. **Accept this CIP** after review of tool list and mutating set.  
2. **Backlog tasks** (only after Accept):  
   - Issues read path (`list` / `view`) + tests  
   - Issues mutate (`comment` / `close` / `reopen`) + tests  
   - Discussions read (GraphQL list/view) + tests  
   - Discussions mutate (comment / close / mark answer) + tests  
   - README allowlist table + Cursor reload note  
3. **Implement** against mocked `gh` / recorded GraphQL fixtures.  
4. **Smoke** from Cursor: list GPy open Discussions; comment on a test thread.  
5. **Close CIP** when REQ-0002 acceptance criteria are checked.

## Backward Compatibility

Additive MCP tools only. Existing `gh_pr_*` unchanged. Clients that do not
call new tools see no behaviour change. After deploy, Cursor must reload MCP
so the new tool schemas appear.
